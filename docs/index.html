Dimension UI · card system

One card, one question

A single card atom with four sanctioned variants, five marks and six colours. Every metric is one value, two sides of one value, or a value across time — and every value is drawn against a baseline it can be judged by.

GitHub Use the component
Colour law
six hues, each with one meaning — a colour never appears for a reason not listed here
Retire anything without a meaning. Orange bars on notional (notional is size → cyan), a second green on equity (result → the one favorable hue), decorative chips with no defined meaning — every hue must map to one of the six above or it does not ship. The single exception is an instrument brand mark, which lives inside its own disc and never colours a value, a bar or a rule.
Shade scale
each hue exists at exactly four strengths — a shade is chosen by role, never by taste

Anatomy
01 label · 02 primary · 03 trend against its own average · 04 window strip with signed deviation · 05 basis + coverage. The 3px rule is the only status signal.
Five rules every card obeys
01

Label states the question, not the source

Two to three words, uppercase. If the label needs a qualifier it belongs in the footnote.

Breaks it: Maker rest age and Maker fill age four cards apart, reading identically.
02

One primary value, in the card's own unit

41px mono, unit at 16px. Never two unrelated numbers at the same weight.

Breaks it: a footnote retained 88.5% that restates the primary verbatim.
03

Every value carries its own shape

A number alone can't be judged. Each card plots the metric against its trailing average — trend for rates, distribution for markout, share for mixes.

Breaks it: progress bars whose scale is never declared.
04

Windows are secondary, inside the card

10M / 1H / 24H, each with its value and a signed bar for its diff against that window's average. Time is an axis, not a card.

Breaks it: four aggregation cards repeating the same four metrics — 16 tiles carrying 4 metrics × 4 windows.
05

Two values only when they answer one question

Maker ↔ taker, realized ↔ unrealized, mean ↔ tail. Both sides can carry the same sign, so they are drawn on one shared signed axis rather than mirrored from a centre.

Breaks it: maker and taker in different sections, so nobody reads the net.

Applied — accounts & legs
the hedge is the unit; the account is how it is funded, the leg is how it is worked
Status is a leg property, not a badge. A status word repeated on every account hides what is still open. Here the P0 / P1 / P2 strip carries complete / active per leg, and only an unclosed leg or an aged P95 turns amber.

The interaction layer is global, not per card.
